RISC-V assembly（call.asm）问题回答

1. 函数参数放在哪些寄存器中？例如，main 调用 printf 时，13 放在哪个寄存器？

   函数参数依次放在寄存器 a0、a1、a2、…、a7 中（第 1～8 个参数）。在 main 调用
   printf 的例子中，13 是第三个参数，放在 a2 寄存器里（汇编对应 `li a2, 13`）。
   （12 即 f(8)+1 是第二个参数，放在 a1；格式字符串地址放在 a0。）

2. 在 main 的汇编代码中，对 f 的调用在哪里？对 g 的调用在哪里？

   main 里既没有对 f 的 call，也没有对 g 的 call。编译器把 g 内联进了 f，又把 f
   内联进了 main：f(8) = g(8) = 8+3 = 11，f(8)+1 = 12 在编译期就被直接算出来，
   变成了一条 `li a1, 12`（立即数 12）。g 和 f 的函数体在汇编里都只是
   `addiw a0, a0, 3`（a0 = a0 + 3）。

3. printf 函数位于哪个地址？

   printf 位于地址 0x6f6（见 main 中的 `jal 6f6 <printf>`）。

4. 在 main 中执行到 printf 的 jal 之后，寄存器 ra 的值是多少？

   `jal 6f6 <printf>` 这条指令位于 0x30，jal 会把返回地址 PC+4 = 0x34 写入 ra。
   因此 ra = 0x34，也就是 main 里 `exit(0)` 的第一条指令 `li a0, 0` 所在的地址。

5. 运行以下代码，输出是什么？（字节序相关）
      unsigned int i = 0x00646c72;
      printf("H%x Wo%s", 57616, (char *) &i);

   输出是 "He110 World"。

   - 57616 的十六进制是 0xe110，所以 %x 打印出 "e110"，前面是 "H"，得到 "He110"。
   - i = 0x00646c72，在 RISC-V 小端存储下，内存中从低地址到高地址的字节依次是
     0x72、0x6c、0x64、0x00，即 'r'、'l'、'd'、'\0'，所以 %s 打印 "rld"。
   - 合起来就是 "He110 World"。

   如果 RISC-V 是大端（big-endian），要让输出和上面相同，应该把 i 设成多少？
   57616 需要改成别的值吗？

   - 大端下，i = 0x00646c72 在内存中的字节顺序会变成 0x00、0x64、0x6c、0x72，
     第一个字节就是 '\0'，%s 会打印空串，输出变成 "He110 Wo"。
   - 要让大端也输出 "World"，需要让低地址处的字节依次是 0x72、0x6c、0x64、0x00，
     也就是把 i 设为 0x726c6400。
   - 57616 不需要改：%x 打印的是整数 57616 的十六进制表示（0xe110），这是对整数值
     本身转换，与内存字节序无关，所以大端下仍是 "e110"。

6. 在下面的代码中，'y=' 后面会打印出什么？（注意：答案不是一个具体值）为什么会这样？
      printf("x=%d y=%d", 3);

   y= 后面打印的是一个不确定的值（不是某个具体的、可预测的数）。

   原因：格式串 "x=%d y=%d" 要求两个参数，但调用者只传了一个参数 3（放在寄存器 a1，
   对应 x）。printf 并不知道实参数量，它会照常从下一个参数寄存器 a2 里取值来打印 y，
   而 a2 并没有被调用者设置，里面是本次调用之前残留的任意内容，所以打印出来的是
   a2 当时碰巧持有的那个垃圾值。
